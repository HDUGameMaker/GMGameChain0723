## 二、Bug 修复具体细节

### 1. 启动、菜单、音频

- 修复启动后绕过开始菜单直接进入游戏：
  - `ConfigRegistry` 加载 `config/ui_main_menu.json`。
  - `src/main.js` 改为先 `boot()` 并显示开始菜单；“新游戏”重置存档，“继续游戏”再加载存档。
- 修复首次启动背景音乐丢失：
  - `AudioSystem.playBGM()` 先记录当前 BGM，再计算淡入音量，避免播放成功但音量为 0。
  - 用户首次交互早于音频异步预加载完成时，初始化完成后会补启动 BGM。
  - 若浏览器拦截自动播放，下一次真实点击/按键会重试。
- 修复弹窗打开时 BGM 被误暂停：
  - `AudioSystem` 不再把 `gamePaused/gameResumed` 作为 BGM 暂停/恢复条件。
  - BGM 现在主要受静音、页面可见性、时段切换影响。
- 修复夜晚 BGM 和地图光照写死时段的问题：
  - `AudioSystem` 读取 `config/global.json` 的 `NIGHT_PERIODS`。
  - `MapRenderer` 读取 `PERIOD_LIGHTING` 和 `PERIOD_TINTS`，不再把上午/下午/傍晚/夜晚写死在渲染层。

### 2. 建造、道路、放置模式

- 修复道路建造进度条异常：
  - 道路进度条字段统一为 `barWidth/barHeight`。
  - 道路进度条补了 `当前/总进度` 文本。
- 修复建筑/道路建造进度跳变：
  - 不再直接使用全局 `timeProgress`。
  - 建筑和道路都按自身 `startTick + startTimeProgress` 推进。
  - 多个建造项每帧独立计算，不会新放下就跳到当前 tick 中段。
- 修复缺少空闲工人时道路无法放置：
  - 道路允许先放置成等待建造状态。
  - 无工人时进度停滞，有空闲工人后自动分配继续建造。
  - 道路存档增加 `workerAssigned/startTick/startTimeProgress`，读档后进度不会错位。
- 修复工棚扩建和道路编辑冲突：
  - `work_shed` 仍保留道路依赖，但也允许贴着已有工棚或仓库类建筑建造。
  - 工棚移动和道路断开后的有效性检查同步支持“道路 / 工棚 / 仓库”三类锚点。
  - 进入建筑放置模式时会退出道路编辑模式；若异常同时存在，地图点击优先执行建筑放置。
- 修复相邻建造要求表达能力不足：
  - `BuildingSystem` 新增 `adjacentRequirementGroups` 解析。
  - 同一组内条件全部满足，多个组之间任一满足即可。
  - 旧字段 `roadRequired`、`adjacentRequirements` 仍兼容，但新配置优先写入 `adjacentRequirementGroups`。

### 3. 任务、新手教程、弹窗

- 修复新手教程启用询问使用浏览器原生弹窗：
  - 新存档首次进入游戏改用游戏内 `tutorial_prompt` 面板。
  - 面板提供“开启教程 / 暂时跳过”，选择前暂停游戏逻辑。
- 修复任务系统自动弹窗不暂停：
  - `PopupManager` 支持弹窗数据级 `blocking: true`。
  - 系统自动弹出的教程任务面板会暂停游戏逻辑。
  - 玩家主动点击任务 HUD 或按钮查看任务不暂停。
- 修复“快捷键大师”不识别空格暂停：
  - 空格键路径补调用 `quest.onPlayerAction('toggle_pause')`。
  - 同时兼容 `e.key === ' '` 和 `e.code === 'Space'`。
- 修复“民以食为天”任务在提前建好狩猎小屋后无法完成：
  - `QuestSystem` 的 `build_building` 任务改为按当前已拥有目标建筑判定。
  - 任务切换和读档恢复时会立即检查当前条件。

### 4. 入侵、军队、殖民地

- 修复入侵提示出现在开始菜单：
  - 删除 `#invasion-widget { display:flex }` 的默认显示覆盖。
  - `InvasionUI` 仅在有活动入侵时添加 `active`。
- 修复入侵战斗结算过于抽象、平局全损且缺少解释：
  - 陆地入侵默认只按 `enemies.invasion.landDefenseDomain` 计算防御领域，当前配置为 `land`。
  - 海军不会错误计入陆地入侵防御。
  - 胜利、平局、失败都会按配置生成复归单位；复归比例和延迟来自 `reviveUnitRate/reviveDelayDays`。
  - 平局会阻止入侵，并按 `drawProtectionDays` 延后下一次入侵。
  - 胜利会按 `victoryProtectionDays` 延后下一次入侵。
- 修复军队数据变化后 UI 不刷新：
  - `InvasionSystem` 和 `ColonySystem` 提交军队变化时会更新 `armyVersion` 并发送 `armyChanged`。
  - `InvasionUI` 监听 `armies/availableUnits/armyVersion/cultureVersion/unitResearch/resourceVersion` 等状态刷新按钮。
- 修复军事系统旧单位/旧阵型残留：
  - 移除旧兵种 `archer/cavalry/chariot/musket` 的解锁路径。
  - 旧阵型 `phalanx/basic_formation/cross_cover/charge/operation` 不再作为有效阵型出现。
  - 地图部署、HUD、渲染与战斗播报改为读取单位配置名。

### 5. 事件、消息、存档、时间顺序

- 修复事件弹窗内容偏左和样式串场：
  - 事件面板内容收窄并居中。
  - 事件描述和选项按钮文字居中。
  - `PopupManager` 切换面板前会重置 `popup-body` 内联样式。
- 修复消息悬停暂停逻辑容易错误恢复游戏：
  - `MessageLog` 移除消息 hover 时直接 `gameLoop.pause()/resume()` 的路径。
  - 避免玩家本来暂停时，移出消息后被错误恢复。
- 修复游戏结束仍可关弹窗或继续保存：
  - `src/main.js` 增加 `_gameOver` 状态。
  - `handleGameOver()` 会停止 `gameLoop`、重置存档并打开 `game_over`。
  - `PopupManager` 禁止关闭 `game_over` 弹窗，并隐藏关闭按钮。
  - `saveGame()` 在 `_resetting` 或 `_gameOver` 时直接返回。
- 修复 `beforeunload` 紧急存档覆盖重置后的空存档风险：
  - `main.js` 删除原 `saveGameSync()` 路径。
  - 自动存档改为监听 `dayAutosaveTick`，从第二天开始保存上一天结算后的状态。
- 修复日结系统读取旧状态：
  - `TimeSystem` 在通知 `periodChange` 前先写入 Store。
  - `dayStart/dayProductionTick/dayAutosaveTick` 在一天第一个 tick 统一触发。
  - 天气系统初始化提前到人口日结之前，人口结算能读取当天粮食修正。

### 6. 加成、产出、探险预览

- 修复“狩猎小屋·林地协作”相邻加成未实际生效：
  - 原配置写在 `foodCapacity` 口径，但狩猎小屋实际产粮走 `production.output`。
  - 已改为 `applyToField: "production"` + `applyTo: "food"`。
  - 相邻伐木集散点后，狩猎小屋每日食物从 `3` 变为 `4`。
- 修复探险物品区域限定加成被忽略：
  - `items.json` 的 `expeditionEffects[].regions` 已在探险结算和预览中按区域过滤。
  - 例如铁质工具组只在 `forest` / `mine_interior` 生效，不再加成其他区域。
- 修复建筑详情显示与实际生产不一致：
  - `BuildingSystem` 的生产逻辑和 UI 预览共用有效工人数、结算频率、产出倍率和相邻加成算法。
  - `building-detail-panel` 展示每人基准、生产人力、结算频率、每日消耗和每日最终产量。

## 三、新机制增加具体细节

### 1. 主菜单和新手体验

- 新增配置驱动开始菜单：
  - 配置文件：`config/ui_main_menu.json`。
  - UI 文件：`src/ui/MainMenu.js`。
  - “新游戏”会重置存档后进入游戏，“继续游戏”读取现有存档。
  - 菜单 logo 即使配置为 `image`，只要有标题文字也会显示。
- 新手教程文档更新：
  - `config/quests.json` 更新道路缺工等待、Ctrl 连续建造、快捷键等说明。
  - `docs/pages/新手教程.html` 补充开始菜单、建造遮罩进度、独立计时、道路等待工人等内容。

### 2. 建造和地图操作

- 新增 Ctrl 连续建造：
  - 放置建筑时按住 `Ctrl` 点击，可连续建造同一种建筑。
  - 默认点击仍保持原行为：成功放置后退出建造模式。
  - 每次连续放置仍逐次执行资源消耗、地块合法性和数量上限检查。
- 新增地图快捷键：
  - `W/A/S/D` 支持按住连续移动地图。
  - 斜向移动会归一化速度。
  - 缩放后移动速度按世界坐标同步调整。
  - `E` 快速开关道路建设模式，复用底部“铺路”按钮逻辑。
  - 输入框、可编辑内容和弹窗打开时快捷键失效，避免误触。
- 建筑建造渲染统一：
  - 动画贴图、静态贴图、文字回退三种建筑本体渲染后，统一进入建造渲染接口。
  - 建造显示效果统一为：目标建筑本体贴图/矩形 -> 灰色遮罩 -> 建造进度条。
  - 建筑名称渲染收敛为共用方法。

### 3. HUD 和每日收支

- 顶部 HUD 资源区重构：
  - 资源按“直接获取资源”和“加工转化资源”分组显示，但 UI 不直接暴露“一产/二产”字样。
  - 左侧资源组分别采用 `2x3` 和 `2x4` 网格。
  - 资源格内“图标 + 当前数量”左对齐，“每日结余”右对齐。
  - 点击资源格会弹出详情，显示每日产出、每日消耗、每日结余。
- 顶部 HUD 信息区重构：
  - 人口、陆军、海军合并到一个竖向信息框。
  - 人口旁边显示每日人口增长预览。
  - 季节、天气、时段、日期、tick 进度合并到一个时间天气框。
  - 视口中心坐标改为同一竖向框中分行显示 `X/Y`。
  - 设置按钮和全屏按钮改为上下堆叠。
- 探险 HUD 缩小：
  - 探险进度从顶部横条改为任务 HUD 下方的小卡片。
  - DOM 使用 `.expedition-card` 列表结构，为多队列扩展预留。
- 顶部浮层位置统一：
  - 新增 `--hud-top-offset` 等 CSS 变量。
  - 消息播报、任务悬浮窗、探险 HUD、暂停提示统一避让顶部 HUD。

### 4. 军事系统、兵种研发、阵型

- 军事单位大修：
  - 陆军分为步兵、骑兵、炮兵三条分支。
  - 步兵链：战士、剑士、火枪手、现代步兵。
  - 骑兵链：骑士、重甲骑兵、双翼机、喷气式战机。
  - 炮兵链：加农炮、坦克、火箭炮。
  - 海军链：木筏、帆船、战列舰、导弹驱逐舰。
  - `config/enemies.json` 新增 `unitBranches` 和 `unitDomains`。
- 新增“兵种研发”面板：
  - 普通科技只提供前置条件。
  - 兵种需要额外消耗灵感完成专项研发后才能训练。
  - `src/ui/panels/unit-research-panel.js` 接入训练入口。
  - 存档保存 `availableUnits`、`unitResearch` 相关状态。
- 陆军阵型重构：
  - 阵型需求支持按 `branch`、`domain` 或具体 `unitId` 匹配。
  - 当前主要使用 `branch`：步兵/骑兵/炮兵覆盖同分支所有时代单位。
  - 新阵型包括步兵互援、步骑协同、骑兵楔阵、步炮协同、诸兵种协同。
  - 固定战力加成前期明显，后期会随着单位基础战力成长自然衰减。
- 训练和军队管理补强：
  - 训练面板增加兵种研发入口。
  - 军队管理和训练面板支持遣散单位返还工人。
  - 入侵 UI 根据防御领域展示军团战力，并标识不适用军团。

### 5. 入侵系统机制

- 入侵规则配置化：
  - `config/enemies.json` 的 `invasion` 现在统一包含强度、首次日期、间隔、贡品、惩罚、复归、免战等字段。
  - `InvasionSystem` 不再使用写死的 `FIRST_INVASION_DAY`。
- 新增贡品免战：
  - 活跃入侵会生成 `tributeFoodCost` 和 `tributeMultiplier`。
  - `InvasionUI` 显示“上交 X 食物”按钮。
  - 成功上交后当前入侵撤退，并按 `tributeProtectionDays` 延后下一次入侵。
- 胜利/平局免战：
  - 胜利后按 `victoryProtectionDays` 延后入侵。
  - 平局后按 `drawProtectionDays` 延后入侵。
- 入侵惩罚可配置：
  - 资源损失率：`punishResourceLossRate`。
  - 人口损失率：`punishPopulationLossRate`。
  - 惩罚后最低人口：`minimumPopulationAfterPunish`。
  - 单位复归比例和天数：`reviveUnitRate/reviveDelayDays`。

### 6. 殖民地系统

- 新增 `config/colonies.json` 和 `src/systems/ColonySystem.js`。
- 接入点：
  - `ConfigRegistry` 加载殖民地配置。
  - `main.js` 初始化、自动存档和存档恢复都包含 `colony` 状态。
  - 紧急/自动存档中保留殖民地进度。
- 发现事件：
  - 玩家人口和总军力达到门槛后，系统按随机间隔检查殖民地发现。
  - 当前配置为每 5-8 天检查一次，检查时 60% 概率弹出，不再每天弹。
- 占领战斗：
  - 殖民地原住民战力基于当前入侵公式按 0.5-2 倍浮动。
  - 高收益殖民地会额外叠加收益折算战力。
  - 占领时陆军按标准战力，海军按 2 倍战力。
  - 占领成功后陆军全损、海军损失一半，损失单位有效战力转为殖民地永久防御。
- 收益和反攻：
  - 已占殖民地每日提供人口和/或资源收益。
  - 殖民地入侵按 7-12 天检查一次，检查时 35% 概率弹出。
  - 殖民地基础防御会参与抵抗。
- UI：
  - `event-panel` 增加殖民地专用渲染。
  - 显示每日收益、原住民战力、可派遣军团、预计损失和防御收益。

### 7. 探险多队列和循环探索

- `ExpeditionSystem` 从单个 `_expedition` 改为 `_expeditions` 队列：
  - `getCurrentExpedition(id)` 兼容旧调用。
  - `getExpeditions()` 返回多队列状态。
  - Store 同步 `expeditionState`、`expeditionStates`、`expeditionQueueLimit`。
- 新增队列上限：
  - `config/expeditions/expedition_global.json` 新增 `baseQueueLimit`。
  - `CultureSystem` 的 `expeditionQueueBonus` 可提高队列上限。
  - `main.js` 开启探索前会检查 `active >= limit`。
- 多阶段探索工人占用规则调整：
  - 多阶段探索占用同一批工人更长时间。
  - 所需工人数取所选区域中的最大 `workerCost`，不再把所有阶段工人相加。
- 新增自动循环：
  - 探索完成一轮后，若 `autoLoop` 为真，会结算本轮收益并重置阶段继续下一轮。
  - `HUD` 对循环完成显示“本轮探索完成，队伍继续循环”。
  - 探险详情面板提供“召回”按钮，调用 `cancelExpedition(expedition.id)` 结算当前携带资源并释放工人/物品。
- 存档兼容：
  - 新存档写入 `{ expeditions: [...] }`。
  - 旧单队列存档仍可从 `state.regions` 结构归一化恢复。

### 8. 事件暂存和默认选项

- `EventSystem` 新增延后处理机制：
  - 当前事件被玩家关闭且尚未选择时，会进入 `_deferredEvents`。
  - HUD 显示 `deferred-event-tray`，点击可重新打开。
  - 当天最后一个时段结束时，未处理事件会走默认选项。
- 新增事件 API：
  - `chooseOption(eventId, optionIndex)`：可从当前事件或暂存事件中选择选项。
  - `openDeferredEvent(eventId)`：重新打开暂存事件。
  - `resolveDefaultOption(eventId)`：按默认选项自动结算。
- 配置字段：
  - 事件支持 `defaultOptionIndex`。
  - 未配置或越界时默认使用第一个选项。
- 存档：
  - `EventSystem.getSaveState()` 保存 `deferredEvents`。
  - `loadState()` 恢复后会同步 Store。

### 9. 人文政策和经济倍率

- `CultureSystem.getEffects()` 扩展：
  - `foodConsumeMul`：人口粮食消耗倍率。
  - `productionMul`：全局建筑产出倍率。
  - `resourceProductionMul`：按资源的产出倍率。
  - `meleeDamageMul/rangedDamageMul/unitHpMul`：军队战斗倍率。
  - `expeditionQueueBonus`：探险队列上限加成。
- `PopulationSystem.getFoodConsumptionAmount()` 接入 `foodConsumeMul`。
- `BuildingSystem` 的每日生产和建筑详情预览接入 `productionMul/resourceProductionMul`。
- `config/doctrines.json` 重做为更明确的人文路线：
  - `rationing`：粮食消耗 -10%。
  - `work_records`：木材 +15%、石料 +10%。
  - `logistics_yard`：解锁补给站。

## 四、编辑器修改具体细节

### 1. 配置加载和保存体验

- `editor/planner-config.html` 新增读取 `config/global.json`：
  - 供时段名称、标签、图标和分析表使用。
  - 若读取失败，会回退到 `['morning','afternoon','evening','night']`。
- 保存体验优化：
  - 自动保存和手动保存都可显示“保存成功”toast。
  - `state.lastSaveToastAt` 限制 1.5 秒内不重复刷成功提示。
- `打开配置编辑器.bat` 已统一端口：
  - `set "PORT=18763"`。
  - 端口检测、服务启动提示和编辑器页面 URL 都读取 `%PORT%`。
  - 不再硬编码 `8080`。

### 2. 建筑编辑器

- 新增“临近要求”编辑区：
  - 支持添加/删除条件组。
  - 支持添加/删除组内条件。
  - 条件类型支持道路、指定建筑、建筑标签。
  - 支持设置 `maxDistance`。
  - 写入字段为 `adjacentRequirementGroups`。
- 兼容旧字段：
  - 若旧配置有 `adjacentRequirements`，编辑器会转换为条件组展示。
  - 若旧配置有 `roadRequired` 且无条件组，会自动生成道路条件组。
  - 保存新结构时会删除 `adjacentRequirements`，并把 `roadRequired` 置为 false。
- 新建建筑默认带：
  - `adjacentRequirementGroups: []`。
  - 原有图标、动画、占地、工人、生产、标签布局等默认结构仍保留。

### 3. 战斗/入侵编辑器

- 入侵配置表单扩展：
  - 首次入侵日：`firstDay`。
  - 间隔下限/上限：`nextDelayMinDays/nextDelayMaxDays`。
  - 防御领域：`landDefenseDomain`，选项来自 `unitDomains`。
  - 贡品资源：`tributeResourceId`，选项来自资源配置。
  - 贡品倍率：`tributeMultiplierMin/tributeMultiplierMax`。
  - 贡品免战天数：`tributeProtectionDays`。
  - 胜利/平局免战：`victoryProtectionDays/drawProtectionDays`。
  - 惩罚比例：`punishResourceLossRate/punishPopulationLossRate`。
  - 最低人口：`minimumPopulationAfterPunish`。
  - 复归比例/延迟：`reviveUnitRate/reviveDelayDays`。
- 入侵强度仍保留公式：
  - `baseA + day * dayMulB + day * day * daySqMulC`。
  - 说明文案已改为提示这些规则均保存到 `enemies.json` 的 `invasion`。

### 4. 兵种和阵型编辑器

- 兵种表单新增字段：
  - `domain`：军种领域。
  - `branch`：兵种类型。
  - `tier`：时代层级。
  - `researchCost`：研发灵感。
  - `prerequisiteUnits`：前置兵种，逗号分隔。
  - `prerequisiteTechs`：前置科技，逗号分隔。
- 新建兵种默认值同步补充上述字段。
- 阵型需求编辑改造：
  - 需求类型可选 `branch`、`domain`、`unitId`。
  - 常用模式是 `branch`，选项来自 `enemies.json` 的 `unitBranches`。
  - 新建阵型默认写入 `{ branch: <第一个兵种类型>, count: 1 }`。
- 编辑器提供回退：
  - 若 `unitBranches/unitDomains` 未配置，会从现有单位的 `branch/domain` 推导选项。

### 5. 人文编辑器

- 新建人文默认字段扩展：
  - `foodConsumeMul`。
  - `productionMul`。
  - `resourceProductionMul`。
  - `meleeDamageMul`。
  - `rangedDamageMul`。
  - `unitHpMul`。
- 人文表单新增“效果倍率”区域：
  - 粮食消耗倍率。
  - 全局产出倍率。
  - 近战伤害倍率。
  - 远程伤害倍率。
  - 单位生命倍率。
  - 按资源产出倍率 JSON，例如 `{"wood":1.15,"stone":1.1}`。
- `resourceProductionMul_json` 会尝试 `JSON.parse()`：
  - 格式错误时显示错误 toast。
  - 成功时写回 `resourceProductionMul` 对象。

### 6. 事件编辑器

- 事件表单新增 `defaultOptionIndex`。
- 选项标题会标记当前默认选项。
- 支持添加选项：
  - 新选项默认 `{ text: '新选项', effects: [] }`。
  - 若事件没有默认选项，会补成 0。
- 支持删除选项：
  - 删除后若默认选项越界，会回退到最后一个选项。
  - 没有选项时默认索引回到 0。

### 7. 探险区域、入口和分析面板

- 探险区域时段收益编辑改为读取 `global.PERIOD_NAMES/PERIOD_LABELS/PERIOD_ICONS`。
- 区域收益摘要和分析面板也使用全局时段配置：
  - 表格行数按实际时段数量计算。
  - 时段显示优先使用图标和中文标签。
- 探险入口说明更新：
  - 每个入口仍可绑定多个探索区块。
  - 多阶段探索占用同一批工人更长时间。
  - 所需人数取所选区块最大 `workerCost`。
- 删除旧的 `differentWorkersPerPeriod` 编辑项：
  - 新建入口不再写该字段。
  - 表单绑定和说明文案同步移除。
