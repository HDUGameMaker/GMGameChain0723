## 一、敌人来源(3 种)

### 1. 第 7 天远古遗迹波次(`InvasionSystem._spawnAncientRuinWave`,InvasionSystem.js:129-217)

- 触发:`_onDayStart` 中 `day % 7 === 6` 发警报,`day % 7 === 0` 生成(每 7 天一波)
- **生成位置:大本营东侧 20 格**(`preferredX = HQ.gridX + 20`,Y 与大本营对齐),从该点按
  曼哈顿环(radius 螺旋)向外找合法格(排除 `x <= HQ.gridX`、水域 `S/W`、已占用格)
- 数量 = 玩家军团数 × 2(上限 10);强度 = 玩家军团平均综合强度 × 1.5(上限 5000)
- 目标:`targetX/Y = 大本营坐标`
- **✅ 已经是"从东方来"** —— R3b 的"统一方向"对波次无需改动

### 2. 城邦派兵(`DiplomacySystem._launchRaids`,DiplomacySystem.js:432-465)

- 触发:每日 `dayStart` 判定(第 311 行),按城邦 `aggression` 概率
  (伪随机:`outpost.id 哈希 + day * 101`,`roll >= aggression` 才派)
- **生成位置:城邦自身位置**(候选:驻军格 / 城邦控制格 / 城邦右下偏移 / 左下偏移)
- 目标:`playerSpawn = config/maps/*.json 的 initialBuildings[0]`(玩家出生点)
- 强度 = 该城邦驻军 compositeStrength;派兵后从驻军中移除该队
- 注意:城邦从**四面八方**派兵 —— R3b 若要求"统一方向",需改此处或调整城邦分布

### 3. 城邦驻军(静态守卫,不移动)

- `getGarrisonArmies` 只用于占格检测(`ArmySystem.js:84`)、交互(`ArmyInteractionSystem.js:57`)
- 驻军不追击(第 12 棒总结写的"8 格内主动追击"**未实现**,驻军只有玩家主动攻击时才战斗:
  `attackGarrison`,DiplomacySystem.js:325)

## 二、敌人移动算法(2026-08-06 已改为共享 BFS 缓存寻路)

**原实现(已被替换)**:贪心曼哈顿直推——每 tick 从 4 邻域选曼哈顿距离最近合法格走 1 格,
无寻路算法,会被地形/建筑卡住(玩家改造地形后敌人可能永远到不了基地)。

**现实现**:共享 `PathfindingSystem`(`src/systems/PathfindingSystem.js`):

1. 每个敌人格缓存自己的 BFS 最短路径(`cell.movePath`),每 tick 沿路径走 1 格并消耗一步
2. 路径**只在建筑变化时失效**:
   - 新建普通建筑:检查其占地格,仅丢弃**路径经过该格**的缓存(只重算被挡住的)
   - 新建桥梁 / 拆除建筑:打开新路线 → 清空全部缓存(每目标下次查询时重算一次 BFS)
   - 其他情况(单位移动、时间流逝)不重算 —— 每 tick 敌人只做 O(1) 的取步 + 占格校验
3. 目标格(玩家大本营)允许不可通行,BFS 以"贴脸"为终点;不可达则原地不动
4. 单位占格(其他敌人/玩家军团)在移动时实时校验,占住就等待,不参与缓存
5. 玩家军团寻路(`ArmySystem._findPath`)也走同一系统(带 avoidUnits 不做缓存,命令时新鲜计算);
   海军/登船规则由 rule 参数区分('naval' / 'embarked')

## 三、玩家军团移动(`ArmySystem`)

### 寻路(`issueMoveOrder` → `_findPath`,ArmySystem.js:850-890)

- **BFS 四方向**,方向顺序 `[右, 下, 左, 上]`
- 障碍判定 `_canOccupyForMovement`:
  - 必须存在地形(`_groundAt`)
  - 不能是建筑占格(`isTileOccupiedByBuilding`)
  - 陆军不能进水(除非桥:`_hasPassableBridge`);海军必须在水中
  - 不能踩其他军团
- 无路径 → `issueMoveOrder` 返回 `no_path`(玩家点击被拒绝)
- 路径用 `previous` Map 回溯重建

### 移动执行(`_advanceMovement`,每 tick)

- 每 tick 移动量 = 军团 `speed`(单位数加权平均)× 全局移动倍率 × 奢侈品加成
- `movementProgress` 累积,整数步逐格消费 `movePath`(shift)
- 目标格被占(其他军团)→ 原地等待(`movementProgress = 0`)
- 路径走完 → `order = hold`
- 移动不触发攻击;攻击由 `ArmyInteractionSystem`(射程内交互 / 点击攻击范围外敌人自动接近)处理

### 与敌人移动的本质差异

| | 敌人 | 玩家军团 |
|---|---|---|
| 算法 | 共享 PathfindingSystem BFS(缓存路径) | 同一系统,BFS(命令时新鲜计算) |
| 速度 | 每 tick 固定 1 格(与玩家不同,移动量不与速度相关——speed 只影响战斗先后手) | 每 tick 按 speed 走多格 |
| 路径重算 | 仅建筑/桥变化时(缓存失效) | 每次下达移动命令 |
| 卡住 | 不可达则原地不动(如隔水无桥) | 绕行(BFS 保证可达则通) |
| 碰撞 | 快照再写入,被占格则等待 | 目标格被占则等待 |

     b) 调整地图城邦分布(城邦集中在东侧/远端),或
     c) 将城邦派兵改为"东侧生成后走向城邦"的样式(与波次同款)
   - 需结合地图分布(24 城邦,base_map.json)决策,待 R3b 与用户讨论方案

## 五、R3b 已实施(2026-08-06,用户确认方案)

### 核心:敌人强度锚定玩家战力,实例挂 buff 不直接改数值

**新增 `src/domain/EnemyBuffs.js`**:
- `makePowerScaleBuff(targetStrength, unit, minScale)` → 生成 `{type:'power_scale', hpMul, attackMul}`
  - 按"目标强度 - 固定项"精确反推倍率(固定项 `(speed-1)×30+(range-1)×50` 不随 hp/attack 缩放),
    实际综合强度与目标误差 ≈ 0(实测 ≤7.5%,含取整)
  - **倍率可 < 1**:玩家战力弱时,进攻单位数值低于 enemies.json 配置基础值(用户明确要求)
  - 下限钳制 `powerScaleMin: 0.2`(低于固定项时保护,避免纸片敌人)
- `applyEnemyBuffs(base, buffs)` → 基础值 × 加成叠加,hp 按扣血比例保持

**玩家战力基准 `_playerPowerBase()`**(DiplomacySystem):
```
playerPowerBase = max(玩家军团平均综合强度, 时代保底)
```
- 军团平均:`ArmySystem.getAverageArmyPower()`(新方法,getArmyStats 含英雄/建筑/时代加成 + cp)
- 时代保底 `powerBaseFloor: [200, 400, 800, 1500, 2500]`(约 1/2/3.5/6/10 个 warrior,可调)

**城邦守军**(CityStateGeneration.js):
- 守军总强度 = `playerPowerBase × (0.5 + level×0.15)`,均分到 2~8 队(队数随距离)
- 每队 = 1 个基础单位 + power_scale buff;实例存 `buffs` + 叠加后的 `hp/maxHp/attack` + 基础值
- 玩家时代推进时 `_syncEraDevelopment` 重建城邦 → 守军自动随时代成长

**城邦派兵**(DiplomacySystem._launchRaids):
- **时间线闸门按距离排名**(rank 1 = 最近;不用 level —— level 会被时代推进的 levelBonus 污染):
  - 1~4 天:不派兵
  - 5~9 天:rank ≤ 3(最近 3 个)
  - 10~19 天:rank ≤ 10(中距离)
  - 20 天+:全部
- **派兵强度按当天基准现算**(不依赖守军实例的旧 buff):
  `raidTarget = playerPowerBase × (0.6 + level×0.2)`,生成 buff 随 combatStats 传入 raid cell

**战斗取值统一走 `EnemyExpansionSystem._getEnemyStats()`**:
- 优先实例自身已叠加数值(实例化时算好)→ 缺叠加值且有 buffs 时 profile 基础 × buffs 现算 → 无 buffs 回退 cell 字段
- `getAllCells()`(渲染/预览)与 `_resolveCellBattle`(战斗)都走它,保证加成生效

**修复的坑**:
- `DiplomacySystem._garrisonStats` 原从 enemies.json 配置表取数值(加成失效)→ 改为优先 army 自身字段
- 城邦兵无 `enemyId` → `_enemyProfile` 命中错误 profile → `_getEnemyStats` 现算分支用错基础值(实测 hp=8 失真)→ 修复为优先 cell 自身叠加值

**配置**(world-factions.json `cityStateGeneration.settings`):
`garrisonPowerBase/PerLevel`、`raidPowerBase/PerLevel`、`powerBaseFloor[]`、`powerScaleMin`、
`raidStartDay/raidMidDay/raidAllDay`、`nearRaidCount/midRaidCount`

**验证**(tmp/qa-r3b.mjs,CDP 真实 Chrome 跑 25 天):
- 时间线:day 2~11 零派兵 → day 12~20 最近 10 城邦 ~1 波/天 → day 21+ 全部(含 level 5 远城邦)
- 强度:在途 70+ 波敌人精确强度 vs 期望(基准×系数)误差 ≤7.5%
- 守军:全部实例带 buffs
- 25 天零报错

- 远古遗迹波次未改(用户明确:"七天一次就行");玩家 0 军团时波次不生成(数量 = 军团数×2 = 0)
