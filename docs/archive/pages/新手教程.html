🕹️ GMGameChain 新手教程

几分钟了解项目工作流：启动游戏 → 配置编辑 → 调试 → Git 版本管理

🚀 快速启动 🧱 基础玩法 🎛️ 配置编辑器 🔍 F12 调试 🔄 Git 版本管理

🚀 快速启动

1. 安装 Node.js（仅首次）

去 nodejs.org 下载 LTS 版本，一路下一步安装即可。

安装后验证：打开终端（CMD 或 PowerShell），输入 node -v 能看到版本号就说明 OK。

2. 启动游戏

双击项目根目录的 启动游戏.bat，会自动：

  1. 检测 Node.js 是否安装（没装会引导下载）
  2. 关闭旧的残留游戏服务
  3. 启动 HTTP 服务器
  4. 打开浏览器访问 http://127.0.0.1:18763

或者手动在终端里跑：

复制cd 项目目录
npx http-server -p 18763 -c-1 --cors
必须通过 HTTP 服务器访问！直接用浏览器打开 index.html（file:// 协议）会报错，因为游戏需要 fetch 加载 JSON 配置文件。

🧱 基础玩法

开始菜单

游戏打开后会先进入开始菜单。点击新游戏会清空旧存档并重新开始；点击继续游戏才会读取已有存档进入正式游戏。

道路建设

  • 点击底部 🛤️铺路 进入道路编辑模式，再点击地格铺设道路。
  • 道路必须紧邻已有道路或建筑，不能直接铺到孤立位置。
  • 道路会消耗配置中的资源；缺少空闲工人时仍可放置，但进度会停滞。
  • 一旦有空闲工人，道路会自动分配工人并继续建造，完成后释放该工人。
  • 在铺路模式下点击已建成道路可拆除；按 Esc 或再次点击按钮退出。

建筑建造

  • 点击底部 🏗️建设 打开建筑列表，选择建筑后在地图上放置。
  • 建筑放下后会显示目标建筑本体，覆盖灰色遮罩，并在遮罩上显示建造进度条。
  • 每个建筑和道路都独立计算建造时间，不会因为同一时刻放置而共享进度。
  • 按住 Ctrl 点击可以连续建造同一种建筑；不按 Ctrl 时，成功放置后会退出建造模式。
  • 每次连续建造仍会单独检查资源、地形、道路依赖、数量上限等条件。

🎛️ 配置编辑器（策划 & 美术）

项目有两个零代码可视化配置编辑器，双击 HTML 文件就能用，不需要写任何 JSON。

策划配置编辑器 planner-config.html

给数值策划和系统策划用，可以编辑：

Tab编辑内容数据源
建筑名称、占地、建造消耗、升级链、生产产出、合成配方buildings.json
资源资源名称、初始值、存储上限resources.json
物品物品属性、探险效果、唯一性标记items.json
事件触发条件、选项分支、效果链events/*.json
探险区域产量矩阵、解锁条件、全局参数expeditions/*.json
地图初始建筑坐标、探险入口位置maps/base_map.json

美术配置编辑器 artist-config.html

给美术同学用，主要功能：

Tab做什么
地图色板修改 6 种地形颜色，迷你地图实时预览
标签布局拖滑块调整建筑名字/进度条/工人数的显示位置
素材引用管理建筑图标/详情图路径，自动检测缺失文件

使用步骤（首次）

1 先启动游戏服务器（双击 启动游戏.bat 或手动 npx http-server），保证 18763 端口开着。

2 打开配置编辑器

方式 A：双击 打开配置编辑器.bat → 选择策划或美术编辑器

方式 B：浏览器直接打开 http://127.0.0.1:18763/editor/planner-config.html 或 http://127.0.0.1:18763/editor/artist-config.html

3 授权写入权限（仅首次）

点击顶部 "选择目录" 按钮 → 在系统弹窗中选择项目的 config/ 文件夹 → 确认。

浏览器会记住这个授权，下次打开不用重新选。

4 开始编辑

改任何字段后约 1 秒自动保存到源 JSON 文件。顶部状态灯变绿 = 保存成功。

策划和美术可以同时打开各自的编辑器，互不影响。 但如果两人编辑同一个 JSON 文件（比如都改 buildings.json），后保存的会覆盖先保存的 — 建议提前沟通分工。
编辑器需要 Chrome 86+ 或 Edge 86+（需要 File System Access API）。 Firefox / Safari 暂不支持自动写回功能。

🔍 F12 开发者工具调试

游戏出问题时，F12 是排查问题的第一入口。

打开方式

  • Chrome / Edge：按 F12，或右键页面 → "检查"
  • 快速切到 Console：按 Ctrl + Shift + J

Console（控制台）— 看报错

打开后切换到 Console 标签页。这里会显示：

  • 🔴 红色错误：代码运行出错，通常说明功能不正常
  • 🟡 黄色警告：不影响运行但建议修复的问题
  • 🔵 普通日志：游戏主动输出的信息（如 [Game] Initialization complete!）
常见报错及解决：
报错信息原因解决
Failed to fetch ... config/xxx.json 没有通过 HTTP 服务器打开 用 npx http-server 启动，不要直接双击 index.html
PIXI is not defined PixiJS 库没加载成功 检查 lib/pixi.min.js 文件是否存在
Cannot read properties of undefined 某个 config 数据缺失或格式不对 检查对应 JSON 文件是否被误改，用配置编辑器修正
Failed to load resource: 404 图片或文件路径不存在 检查 assets/ 目录下对应文件是否存在

Network（网络）— 看文件加载

切换到 Network 标签页，刷新页面。可以看到所有 JS/CSS/JSON/图片的加载情况。红色 404 说明文件缺失，红色 (failed) 说明网络不通。

调试技巧

  • 在 Console 中输入 window.__game 可以访问游戏实例，查看所有系统状态
  • 例如 window.__game.systems.resource._resources 查看当前资源数据
  • 按 Ctrl + Shift + C 然后点击页面元素可以查看对应 HTML/CSS

🔄 Git 版本管理

配置改错了想回滚？多人协作需要同步？用 Git + 图形化工具管理。

仓库信息

仓库地址git@github.com:HDUGameMaker/GMGameChain0723.git
Web 页面https://github.com/HDUGameMaker/GMGameChain0723
主分支master

克隆仓库到本地

复制git clone git@github.com:HDUGameMaker/GMGameChain0723.git

或在 Fork 中：File → Clone → 粘贴仓库地址 → 选择本地目录 → Clone。

推荐使用 Fork（git-fork.com），免费、轻量、Windows 原生，比命令行直观很多。

Fork 安装 & 首次设置

  1. 去 git-fork.com 下载安装
  2. 打开 Fork → File → Clone Repository
  3. 填入仓库地址（GitHub / Gitee 等），选择本地目录，点 Clone
  4. 克隆完成后就能在 Fork 里看到所有文件

日常工作流

1 改配置前先 Pull（拉取最新代码）

工具栏点 Pull 按钮（或 Ctrl+Shift+P），保证本地是最新版本，避免覆盖别人的修改。

2 编辑配置 / 美术资源

用配置编辑器改 JSON，或替换 assets 里的图片。Fork 会自动检测到文件变化，在 Changes 面板列出所有改过的文件。

3 Stage（暂存）要提交的文件

在 Changes 面板中，勾选你想提交的文件，或者直接点 Stage All。文件会从 "Unstaged" 移到 "Staged" 区。

建议只勾选你真正修改过的文件，不要把自动生成的文件（如 manifest.json）混在一起提交。

4 Commit（提交）

左下角写提交信息，格式建议：

建筑: 农田产出从 5 提高到 7
事件: 新增"暴风雪"事件，morning 触发
美术: 替换工棚图标，修正绿色背景

写好后点 Commit 按钮。

5 Push（推送）

工具栏点 Push 按钮，把本地提交推送到远程仓库，别人就能看到你的改动了。

改错了怎么办

情况操作
还没 Commit，想撤销某个文件的修改 在 Changes 面板右键该文件 → Discard Changes
已经 Commit 但还没 Push 菜单 Repository → Undo Last Commit（撤销提交但保留文件修改）
已经 Push 了 菜单 Repository → Revert Commit（生成一个反向提交）
想回到某个历史版本 在提交历史中右键某个旧 Commit → Reset → 选择模式
Reset 操作会丢失历史，Push 过的 Commit 不建议 Reset。不确定时先问一下团队里熟悉 Git 的人。

分支管理

多人协作时建议每人开自己的分支，改完再合并：

  1. Fork 工具栏点 Branch → New Branch → 输入分支名（如 planner/balance-tuning 或 artist/icons-update）
  2. 在新分支上正常 Commit / Push
  3. 改完测试没问题后，切回 main 分支，Merge 你的分支
如果团队用 GitHub / Gitee，可以在网页上创建 Pull Request，让同事 Review 后再合并，更安全。
