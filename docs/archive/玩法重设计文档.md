# 游戏玩法重设计文档

> 本文档是对现有游戏玩法的大刀阔斧重设计总结,作为后续代码改造的设计依据。
> 核心思路:**做减法,聚焦一根主线**。
> 本文档只讲玩法层面,不含代码实现方案。

---

## 一、设计背景与目标

### 诊断出的原有问题
- **系统多但浅**:18 个系统堆叠,各自独立,缺乏交叉。
- **难上手**:资源种类繁杂、加工链长、人口参与生产增加门槛。
- **上手后不知道做什么**:缺少明确的长期目标和核心动词。

### 重设计目标
一根合格的核心主线需要同时具备:
1. 具体的长期目标
2. 有趣的核心动词
3. 能消耗/驱动其他系统的能力

**北极星**:多个系统交织,但易上手,挖掘却有深度。

### 核心体验(玩家体感目标)
> 通过规划资源做加法和乘法,让自己的成长高于敌人的成长,并且不断提升自身的成长效率,最终获得数值上的爽感。

### 挖掘深度的分布(实现时这几处必须真有深度)
深度不压在单一系统上,分散在五条矿脉,挖穿任一条都不该直接通关:
1. 兵种 combo / 配装(战斗半边的全部深度)
2. 漏斗形态 / 地形耦合(经济深度)
3. 炼金乘法优化(成长深度)
4. 空间修剪纪律(战术深度)
5. 建筑摆放(大建筑高危带来的策略)

---

## 二、一句话定位

末世炼金征服游戏:用扁平的基建经济攒黄金,黄金点燃炼金(产出乘法 + 占有术)和军队,靠"清敌 -> 占地"把地图铺满来通关;敌人按 x2 指数扩张,清不过来就被淹没。

---

## 三、主线

**占领地图是终极目标。** 各系统角色:

| 系统 | 角色 |
|------|------|
| 炼金 | 放大引擎(给基础产出做乘法 + 产出占有术通关工具) |
| 战斗 | 手段(清掉格子上的敌人,为占领开路) |
| 黄金 | 接口/瓶颈(同时供给炼金和战斗的唯一资源) |
| 生存 | 底盘(不被敌人扩张淹没) |

---

## 四、资源系统(重做)

### 删减
砍掉原木/木板/铁矿/铁锭/煤炭等繁杂资源与加工链。

### 四种资源

| 资源 | 类型 | 说明 |
|------|------|------|
| 木头 | 基建资源 | 自动产出,不需人口 |
| 石头 | 基建资源 | 自动产出,不需人口 |
| 食物 | 基建资源 | 自动产出,不需人口 |
| 黄金 | 导向资源 | 三个基建的获取最终都指向黄金 |

### 关键规则
- **人口与基础资源循环斩断**:人口不再参与生产,降低上手门槛。
- 基建资源自动产出,无需工人分配。
- 三种基建资源靠**漏斗形态 + 地形耦合**区分(而非各自独立 sink):
  - 木要林、石要山、食要平原 —— 占哪块地决定能产出什么资源配比。
  - 转换比/延迟各不同。
  - 占领系统反过来喂资源系统,主线更紧。
- **黄金是唯一瓶颈**:同时供给炼金和战斗,每个决策点都在做"酿药 vs 招兵"的取舍。

### 黄金的三个去向
1. 招募士兵(组成军队)
2. 升级建筑数量上限
3. 炼金

---

## 五、核心循环

```
基建(木/石/食 自动产出) -> 产金设施 -> 黄金
黄金 -> ①招兵  ②升建筑上限  ③炼金
炼金 -> ①给基建产出上乘法  ②产出"占有术"
占有术 + 建筑 -> 标记格子,铺满地图 = 通关
敌人在未标记格刷新 -> 兵清敌 -> 术占地 -> 建筑固土
```

---

## 六、占领机制 / 占有术

- **占有术**是炼金术的一种,标记格子后该位置不再出现敌方单位(首次刷新)。
- **建筑**(已建造的)也算占有(标记格子)。
- 通关 = 用占有术 + 建筑铺满整张地图。
- **建筑数量上限**:为平衡引入,消耗黄金 + 资源升级上限。逼玩家在超上限时用占有术进行大规模占领。

### 占有术的三个独立身份
1. 不占建筑数量上限
2. 能施在不可建地形(如水域)—— 唯一能赢下这些格子的方式
3. 提前预铸安全感(为准备扩张的区域打安全)

### 占有术 vs 建筑

| | 建筑 | 占有术 |
|---|------|--------|
| 产资源 | 是 | 否 |
| 占建筑上限 | 是 | 否 |
| 可施不可建地形 | 否 | 是 |
| 被扩张覆盖 | 整栋毁 | 被抹掉 |

---

## 七、敌人与扩张(失败来源)

### 敌人
- 敌人具象化,刷在格子上。
- 随日期推进,刷新数量和格子数变多。
- **首次刷新只在空白格**(不刷在建筑/占有术上)。

### 扩张机制(x2)
- 每个敌人格有倒计时;倒计时结束前没清掉就向四周扩张。
- **扩张 x2**:一个格扩一格,两个格扩两格,每回合翻倍。
- 扩张能覆盖一切玩家地盘:
  - 占有术被抹掉
  - 建筑被摧毁(2x2/3x3 大建筑碰到就整栋没,**不分块掉血**)
  - 被覆盖的格变敌方格

### 两轴压力模型(关键设计)

压力分成两根独立的轴,各有各的技能和失败模式:

| 轴 | 来源 | 玩家技能 | 类型 | 失败模式 |
|----|------|----------|------|----------|
| 空间轴 | 格子数 x2 扩张 | 持续修剪,压住敌方格子数 E | 战术/反应型 | 被淹没 |
| 数值轴 | 单格敌兵强度按日期曲线增长 | 把军队+炼金乘法堆到能清当日强度 | 战略/数值型 | 清不动 |

- x2 是**空间轴**(格子数翻倍),不是敌方人口翻倍。
- 单格敌兵数值是**按日期配置的曲线**,开发者可控 —— 这是难度调节主旋钮。
- "成长超过敌人"的体感活在**数值轴**(比单格强度曲线),不是格子数。
- 炼金横跨两轴:乘法养军队 = 喂数值轴,占术 = 喂空间轴。

---

## 八、胜负条件

- **胜利**:占有术 + 建筑铺满整张地图(所有可占领格)。
- **失败**:被敌人 x2 扩张淹没(清不过来,指数膨胀失控)。

---

## 九、玩家游玩曲线(三阶段)

### 第一阶段 · 点火
放基建采集器 -> 产金 -> 攒黄金。敌人稀少。学资源漏斗。
- 起手送一部分黄金,让玩家第 1 回合就能做"炼金/招兵/升上限"三选一,消除无决策等待。

### 第二阶段 · 点燃
第一笔黄金 -> 解锁炼金 + 招兵 -> 首波敌人 -> 学核心动作"清敌 -> 占术 -> 占地"。黄金分配成为主决策。

### 第三阶段 · 拉锯
地图占过半,敌人 x2 扩张,"占地 vs 被拆地"竞速。占术施法速度 vs 扩张速度是生死线,最后几格是高潮。

### emergent 特性
- 占地越多,敌人能刷的空格越少;但时间推进让单格强度变大 —— 压力自然集中在收尾。
- **大建筑 = 高效但高危**:3x3 被蹭一格就整栋没,逼玩家把大建筑塞进安全腹地、前线放小建筑/占术 —— 建筑摆放有策略深度。

## 十、设计约束与注意点(实现时必须遵守的 guardrails)

1. **占术成本必须随金产出一起通胀**:保持"贵到铺不满"。一旦后期金子泛滥能随手铺全场,占术就退化成纯吞吐,空间决策消失。
2. **兵种 combo 空间必须足够宽**:战斗是自动结算、局内无决策,兵种组合/配装是整个战斗半边的全部深度。combo 空间窄 = 战斗半边只剩"买数值最大的兵"。
3. **单格强度曲线不能定太死**:否则变成"第 N 天必须有多少军队否则软锁"的固定检查点。让"我成长够不够快"成为真问题,靠军队 scaling 的方差(combo 选择)。
4. **第一幕的 dead-time 靠"起手金 + 产出密度"双管齐下**:起手金是点火,产出速率(决策到达密度)是续命,两个都要调。
5. **三条资源漏斗要大致平衡、强 situational**(某地形下谁更优):否则出现一条最优漏斗、另俩凑数,违背"做减法"。
6. **扩散必须可预测 + 倒计时可见**:大建筑被蹭整栋毁是高惩罚,前提是玩家能看见敌人即将扩散到哪里(优先吃玩家相邻格而非随机),否则就是纯惩罚、体验是挫败。
7. **大建筑整栋毁是设计意图,不是 bug**:这是"大建筑=高危"emergent 策略的来源。

## 十一、待定 / 暂缓项

以下尚未决定,实现时可按合理默认值先做,但需标注为可调:

- **战斗结算细节**(兵怎么清敌、兵种克制、阵型)—— 本轮玩法层面暂不讨论,但兵种 combo 宽度是硬约束(见约束 2)。
- **人口是否完全删除**(还是保留为某种压力)—— 已从生产循环斩断,是否彻底移除待定。建议默认:养兵维持消耗,给食物一个独立 sink。
- **食物砍人口后的归属**—— 建议默认:养兵,给三个基建资源各一个独立职能。
- **占有术的具体成本**(材料/上限/冷却)—— 待定,但受约束 1 约束。
- **占有术是否需要邻接/射程约束**(只能从已有领地往外扩 vs 可远程施法)—— 待定。邻接约束会把吞吐游戏变空间征服游戏,但会牺牲"远程预铸安全"的便利。这是个 feel 取舍。
- **敌人扩张方向**(优先吃玩家相邻格 vs 随机)—— 建议默认:优先吃玩家相邻格(配合约束 6)。
- **节奏曲线**:一局多长、地图多大、首敌第几天、占术/炼金/招兵分别什么时机解锁、产出密度 —— 待定,是下一个该定的宏观项。
- **炼金系统的具体深度**(原 Magnum Opus 五阶段等是否保留)—— 待定。
- **单格强度曲线的具体形态**(线性/多项式/阶梯)—— 待定,是数值轴的骨架。

## 十二、原系统删减清单(提案,待最终确认)

从现有 18 系统中,拟做如下处理:

- 科技树 -> 合并入炼金解锁
- 文化树 / 教义 -> 删减或合并
- 道路 / 驯兽 / 火把光照 / 天气+季节 -> 最小化或移除
- 15 单位 / 5 阵型 -> 简化为少量兵种 + 相克 + 阵型(combo 宽度优先于数量)
- 繁杂资源与加工建筑 -> 移除(见第四节)

> 注:以上为重设计方向上的提案,尚未逐项最终确认。改造时建议逐系统核对,确认一个删/改一个。
