# 建筑、经济、固定地图与美术补全设计

## 目标

在唯一的 384×384 固定战略地图上，补齐建筑详情与建筑内人口配置，严格拆分农业、商业、贸易三个模块，重绘参考图风格的大陆/山脉/水系布局，增加可开发资源点，恢复全天战争迷雾，并沿用原项目的素材板生产方式为缺失、重复或错误绑定的美术逐项生成独立资源。

本设计只修改 `GM GameChain2026` 主版本，不处理 `GM GameChain2026 Early Assess`。

## 1. 建筑详情与人口配置

所有已建建筑统一使用完整详情页。详情页至少显示：建筑大图、名称、类别、时代、状态、说明、解锁来源、岗位、当前效果、投入、产出、相邻加成与可执行操作。无生产配方或无岗位的建筑也必须显示其被动功能与“无需人口”，不允许出现只有移动/拆除操作的空详情。

有岗位的建筑在自己的详情页配置人口：

- `-` 与 `+` 调整该建筑当前人口。
- 显示空闲人口、岗位上限、每人产出与当前每日总产出。
- 分配不能超过空闲人口和建筑岗位上限。
- 调整后立即刷新建筑、HUD 和相关汇总页。
- 配置结果进入现有建筑存档记录，不建立第二套人口池。

## 2. 农业、商业与贸易

### 农业

农业必须依赖实际农田建筑。每座农田在建筑详情内选择一种已解锁作物并配置农业人口。不同作物具有不同的基础产出、地形适配、时代/科技条件和附加效果。换种在下一个结算周期生效，避免同一天反复切换套利。

农业总览保留，但只负责：

- 汇总全部农田、作物、人口和预计收益。
- 显示未种植、缺人口或地形不适配的农田。
- 提供定位/打开具体农田详情的入口。

农业总览不能直接修改人口或作物。

### 商业

商业是城市内部经济，不等同于贸易。市场、商馆、钱庄、交易所等商业建筑拥有各自的黄金产出与唯一 Buff。

- 商业建筑至少分配 1 人才启用金币产出和 Buff。
- 增加人口提高金币产出，但唯一 Buff 不按人数重复叠加。
- 不同商业建筑的 Buff 可以按配置规则组合，同 ID Buff 不重复计算。
- 商业详情显示基础金币、当前金币、Buff 状态及生效条件。

### 贸易

现有城邦贸易路线、资源交换、路线容量与风险归入独立“贸易”模块。原先把贸易称为商业的按钮、标题与说明统一改名，不改变已经合法的贸易路线存档 ID。

## 3. 建筑分类与解锁

建造菜单按住宅、农业、采集、工业、商业、科研、人文、军事、防御、海军、行政等类别展示。每项建筑使用一个规范类别，必要时用标签支持次级筛选。

未解锁建筑仍可查看，但必须显示锁定原因。有效解锁条件包括：

- 所需时代。
- 所需科技。
- 所需人文制度。
- 前置建筑、地形或资源节点。
- 文明限定。

显示层与 `BuildingSystem` 使用同一个解锁判定结果，避免界面显示可建但系统拒绝，或反向不一致。

## 4. 固定地图重绘

采用模板驱动的离线固定地图方案。先定义低分辨率宏观区域模板，再细化为 384×384 格子并提交最终 JSON；运行时不得生成或重排地图。

参考图的布局特征转化为以下固定规则：

- 多块大型大陆、内海、海峡、半岛和少量岛链。
- 山脉以连续山系出现，森林沿山麓、水源和湿润区成片分布。
- 草原与可建设平原保持连通，干燥地形集中成区。
- 水域仍占 15%–20%。
- 玩家出生点位于右中部大陆约 `(270, 180)`，最终坐标可以在邻近安全格内微调。
- 出生区附近必须有连通建设空间、森林、石料、食物、普通矿点和可到达海岸。

24 个城邦和 96 个野外目标允许按新地图重新预放置。新坐标必须固定、唯一、域兼容、可达，并满足出生安全距离。

## 5. 地图资源节点

资源节点是独立固定地图层，记录 `id`、`type`、`gridX`、`gridY`、`terrain`、`rarity`、`capacity`、`remaining`、`recoveryDays` 和 `developedByBuildingId`。

常用资源严格限定为四种主资源：黄金、石头、食物、木头。不得新增铁矿、黏土或其他基础经济资源：

- 数量多，在所有适合地形上均匀分布。
- 长期存在，不因普通采集永久消失。
- 每块主要大陆保证同时拥有黄金、石头、食物和木头；黄金可以比另外三种稍稀疏，但仍属于常用资源并保证区域可获得性。

稀有节点使用现有奢侈品系统，例如香料、宝石、马匹等；它们不加入四资源经济：

- 数量较少，遵循地形约束。
- 可耗尽，并在较长周期后恢复。
- 达到零储量时暂停依赖它的生产，但不会改变节点坐标。

依赖资源节点的建筑必须建在匹配节点上。建成后节点显示“已开发”状态，建筑被拆除后释放该节点。

## 6. 全天战争迷雾

战争迷雾不再与昼夜开关绑定，白天和夜晚始终启用：

- 从未探索：近乎不透明黑雾。
- 已探索但当前不可见：显示暗色地形记忆，并隐藏实时单位/资源变化。
- 当前可见：正常显示。

白天基础视野半径为 10 格，夜晚为 6 格。建筑、军队、英雄和科技提供显式加成。缩放只改变显示比例，不改变视野格数。探索记录与当前视野状态进入存档。

## 7. 美术审计与素材板重绘

先生成资产清单，检查每个内容 ID 的配置路径、实际文件、可解码性、尺寸、哈希和使用界面：

- 文件不存在、损坏或尺寸过小：缺失。
- 不同内容使用同一文件或相同图片哈希：重复。
- 文件存在但配置未绑定、运行时加载失败或错误回退：错误绑定。

处理规则：

- 已经独立、清晰且运行正常的图片保留。
- 缺失图片全部新画。
- 重复组保留最匹配的一项，其余内容逐个重画。
- 错误绑定先修正路径；若内容本身不匹配则重画。

原始开发报告记录的主要美术生产 Skill 是 `E:\SKILLS\游戏图标\assetify\SKILL.md`，用于批量素材板生成、透明度检查、伪棋盘格清理、切片和联系表质检；`generate2dsprite` 仅被评估，没有用于 2.5D 招募立绘。

当前开发机器没有 `E:\SKILLS` 下的 `assetify` 文件，也没有迁移到 Codex skills 目录的副本。旧文档未记录仓库地址，公开网络与可验证技能目录中也没有找到同一 Skill，因此不得下载无关同名项目或声称已经恢复原 Skill。

已从 OpenAI 官方 `openai/plugins` 仓库下载并核对 `game-studio/sprite-pipeline` 工作流。该流程适合动画条带，当前兵种需求仍是单张 2.5D 招募立绘，所以实施时以已安装的 `imagegen` 生成整板素材，复用项目内 `scripts/slice_asset_board_windows.py` 完成 Windows 切片、透明度检查、伪棋盘格检查和联系表质检；只有未来增加逐帧动画时才使用官方精灵条带归一化脚本。此组合等价覆盖原 `assetify` 在本项目中实际承担的职责。

需要生成的内容包括：

- 建筑详情图：图 1 的 2.5D 历史策略风格，独立轮廓，适配详情大图。
- 兵种卡图：按时代、文明和分支设计装备与姿态，不以简单换色代替独立内容。
- 资源节点图：适合地图小尺寸辨识；四种主资源分别表现木头、石头、食物和黄金，奢侈品图标继续使用独立的稀有节点画面。
- 商业建筑：从造型上区分市场、商馆、钱庄、交易所等用途。

正式验收要求运行时需要的美术缺失数为零、异常重复数为零。加载异常时可以显示带内容名称的统一回退卡，但回退不算正式交付完成。

## 8. 存档兼容

继续使用 v9 存档。旧建筑记录在恢复时补齐默认岗位、作物、商业状态和美术路径。合法的贸易路线 ID 不变。

旧地图存档保留旧地图身份和已有坐标；新游戏使用重绘后的固定地图。地图资源、迷雾探索、农田作物与稀有资源恢复计时均需序列化并在恢复时校验。

## 9. 验收

验收至少覆盖：

- 所有建筑详情都有实质内容。
- 人口只能在具体建筑详情中调整。
- 农业总览只汇总/定位，农田详情可选作物。
- 商业与贸易入口、状态和收益逻辑完全分离。
- 建筑分类与时代/科技/人文锁定显示和执行一致。
- 新地图符合参考图的宏观分区，出生点位于右中部，水域为 15%–20%。
- 主要大陆均匀拥有黄金、石头、食物、木头四种常用资源，不新增第五种基础资源。
- 白天/夜晚迷雾和 10/6 格基础视野正确。
- 缺失、重复和错误绑定美术均已处理并在主要界面实际显示。
- Node 测试、语法检查、固定地图/资产校验和 Chromium 实机旅程全部通过。
