# 人口、探索营地与时代指引修复设计

## 目标

1. 已招募的平民人口不会因为食物短缺而逃离或死亡；缺粮只降低满意度、消耗现有食物并阻止自然增长。
2. 大本营进入建造序列且不设单建筑数量上限，仍受全局建筑上限、资源成本和占地规则限制。
3. 洞穴不再依赖道路。玩家必须在洞穴入口格上建造探索营地，之后点击该格即可打开探险准备。
4. 时代窗口同时列出所有晋升条件、当前数值、完成状态和时代星获取方式。

## 数据与边界

- 不修改并行进程维护的 `config/historical_content.json`、`assets/map/generated/` 和 `tmp/`。
- 为避免覆盖工作区中正在变化的 `config/buildings.json`，探索营地放入独立配置 `config/exploration-buildings.json`，由 `ConfigRegistry` 合并。
- 大本营数量限制使用独立运行时覆盖配置，避免重写并行版本的建筑总表。
- 探索营地为 1×1 行政建筑，只能精确覆盖 `map.expeditionEntrances` 的坐标；山地不可建造规则仅对这一明确契约例外。

## 交互流程

裸洞穴被点击时，系统提示“请先在洞穴入口上建造探索营地”，不再检查道路。探索营地建成后，同一格的洞穴点击事件验证建筑存在并打开探险准备。建筑详情中也显示该营地绑定的洞穴名称和“开始探索”按钮。

教程探索任务文案明确说明：打开建造菜单，选择探索营地，覆盖洞穴入口，完成后点击探索营地开始探索。

## 时代指引

`EraSystem.getAdvancementRequirements()` 返回下一时代、文明选择、科技完成率、人文完成率和时代星四项条件。UI 逐项显示当前值与目标值，不再把唯一信息藏在禁用按钮的 `title` 中；同时列出科技、人文、阈值和特色建筑的时代星奖励。

## 验收

- 连续缺粮不会改变人口数，食物仍被消耗、满意度仍下降、自然增长仍停止。
- 大本营出现在建造菜单且第二座可合法放置。
- 探索营地不能放在普通山地，只能覆盖洞口；道路为空也能探索，裸洞口不能探索。
- 时代条件 API 和真实 DOM 同时展示四项条件及进度。
- 全量 Node 测试、语法检查与 Chromium 新游戏冒烟通过。

## 山体视觉追加设计

山体不再使用由边缘向中心变化的等高线式灰色色带，也不在大地图上铺设放大的写实山贴图。山麓与山脊仍占用原有方格和通行规则，但视觉由格内独立岩块组成：山麓每格 1–2 块，山脊每格 2–3 块，相邻格共同形成完整山群。

每块岩石由梯形顶面、倾斜正面、深色侧面和可选风化裂纹构成，使用多套灰、褐、砂岩调色板与四类轮廓。坐标哈希保证同一地图位置每次载入保持一致，同时不同山格不会机械重复。所有岩块均在所属方格内绘制，保持纯方格战略地图的边界、资源点和洞穴交互不变。
