# 资源节点与军事功能可发现性设计

## 目标

修复“地图存在资源数据，但玩家找不到、放不上采集建筑、找不到兵种研发和英雄功能”的体验断点，同时保持固定大地图坐标、资源密度、存档兼容和四基础资源经济不变。

## 已确认现状

- 固定地图已有 400 个石料节点、400 个黄金节点和 60 个奢侈品节点。
- 20 种奢侈品各有 3 个节点，密度已满足“明显低于基础资源”的要求，无需重建地图。
- 石料节点均为单格 `R` 地形，但 `stope` 与 `stone_quarry` 仍是 2×2，占地与节点表达不一致。
- 石料节点使用与山体相同的低矮石堆，缺乏资源标志感；奢侈品运行时使用旧 SVG，不满足独立方形地图贴图的表现要求。
- 兵种研发只能从训练面板二次进入；英雄只能从酒馆建筑详情进入，底栏没有直达入口。

## 方案

### 石料节点与石矿

- 不重建固定地图，不移动现有石料节点。
- 通过独立运行时覆盖配置把 `stope` 和 `stone_quarry` 均改为 1×1，继续要求覆盖空闲 `stone` 节点并位于 `R` 地形。
- 石料节点显示为单格方形标志：浅黄土地块、清楚的描边、中央立体石堆图。建筑建成后节点仍保留但降低透明度，表示已开发。
- 放置与认领仍由 `ResourceNodeSystem` 和 `BuildingSystem` 负责；存档字段不变。

### 奢侈品节点

- 保持 20 种、每种 3 个节点，不提高密度。
- 为丝绸、玉石、茶叶、香料、象牙、葡萄酒、香料香、宝石、珍珠、琥珀、毛皮、染料、可可、咖啡、瓷器、香水、银器、马匹、盐、棉花生成 20 张独立透明 PNG。
- 路径统一为 `assets/resource-nodes/luxuries/<luxuryId>.png`，运行时按 `luxuryId` 解析，不修改另一进程维护的 `historical_content.json`。
- 地图上用单格方形紫金标志承载对应图标；贸易站继续为 1×1，并且只能覆盖空闲奢侈品节点。

### 山体碎石填缝

- 保留现有浅黄土地基与跨格大岩柱。
- 对每条右侧共享边生成上、下两组碎石；对每条下侧共享边生成左、右两组碎石。
- 所有变体继续由坐标哈希稳定选择，重载不跳变；碎石仍位于大岩柱下方，并服从底脚纵深排序。

### 兵种研发与英雄入口

- 底栏新增“兵种研发”按钮，直接打开 `unit_research`。
- 底栏新增“英雄”按钮，直接打开 `tavern_heroes`，该面板始终展示已招募英雄名册。
- 没有投入使用的酒馆或酒馆大厅时，英雄页顶部显示“建设酒馆后即可招募英雄”的醒目锁定提示，并禁用招募操作；已有英雄仍可查看。
- 原训练面板和酒馆建筑详情中的入口继续保留，形成多入口但单一面板的数据流。

## 美术规格

- 20 个图标使用统一历史策略游戏 2.5D 小道具风格、左上柔光、暖色描边、无文字和水印、真实透明背景。
- 每个主体在近方形画布中居中，缩小到单格后仍能凭轮廓识别。
- 批量生成后逐张检查主体、透明通道和裁切边界；不把整张资产板直接贴入游戏。

## 验收

- 两种石料采集建筑运行时占地均为 1×1，并能覆盖单格石料节点完成认领和产出。
- 石料、黄金与奢侈品在地图上均有可辨认的单格资源标志。
- 20 种奢侈品节点分别解析到 20 张存在且可解码的 PNG；贸易站覆盖节点后可继续采集对应奢侈品。
- 连续山体横向和纵向接缝均至少拥有两组碎石填充。
- 底栏可以一步打开兵种研发和英雄名册；无酒馆时英雄页清楚提示建造条件。
- Node 全量测试、JavaScript 语法检查和 Chromium 冒烟测试通过。

## 并行修改保护

不修改或暂存另一进程维护的 `config/buildings.json`、`config/historical_content.json`、其他脏配置与 `tmp/`。石矿占地通过当前干净的 `config/building-runtime-overrides.json` 实现；奢侈品图标通过运行时路径解析实现。
