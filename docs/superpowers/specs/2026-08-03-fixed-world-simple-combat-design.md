# 固定大世界与简化战略战斗设计

日期：2026-08-03
状态：已由用户确认设计方向，待书面规格复核

## 1. 目的与覆盖关系

本设计替代《Complete RTS × SLG Game Design》中“运行时程序化世界”和“精细六阶段战斗”的要求。其他已确认范围保持不变，包括 24 个城邦、96 个野外目标、以真实城邦为目标的殖民、七时代、57 个文明、72 名英雄、任务链与长期后果、美术优化、音乐和音效。

游戏只提供一张正式战略地图。地图在开发阶段离线生成和人工校正后作为固定配置提交；运行时不根据种子重新生成地形，也不重新计算城邦、野外目标或资源点坐标。

### 1.1 完整但适度简化

新增机制采用“最小完整闭环”标准：必须有真实数据、运行时行为、可见界面、存档恢复和自动化测试，但不继续叠加非必要的第二层、第三层子规则。城邦 AI、外交、贸易、殖民、英雄、任务和战斗各保留一个清晰权威状态与一条完整玩家路径；避免为同一概念建立多个并行系统、重复货币、过细阶段或只服务少数边缘情况的模拟。

既定内容数量仍需满足，但数量记录可以共享经过验证的通用执行器。例如 96 个野外模板共享有限的生命周期模式，72 名英雄共享统一的等级、任命和技能框架，任务链共享同一个长期后果队列。

## 2. 固定 384×384 世界

### 2.1 地图身份

- 正式地图尺寸固定为 `384×384`，格子尺寸保持 `60`。
- 正式地图 ID 为 `grand_map_v1`，数据来源标记为 `fixed_static`。
- 所有正常新游戏加载同一份地形、出生点和初始目标分布。
- 旧 v5–v8 存档继续通过 v9 迁移读取 `legacy_static/base_map_v1`；不得把旧存档坐标静默映射到新地图。
- 新 v9 存档只记录地图 ID、动态占领/清除/地形变化及系统状态，不重复保存完整 384×384 基础地形。

### 2.2 地形制作方式

采用“离线生成一次，再固化”的方式：

1. 使用确定性离线工具生成具有自然随机感的大陆、海岸、岛屿、河湖和生态分区。
2. 使用固定制作种子，仅用于重现构建产物，不进入新游戏界面，也不影响运行时地图。
3. 对出生区、港口、通路、城邦间距、野外目标密度和视觉重复进行校验与必要的人工修正。
4. 将最终地形写入受版本控制的固定地图配置。运行时只读取该配置。

最终地图必须实际包含 `R/G/D/F/M/W/B/S` 八种地形代码，具有草地、普通土地、森林、岩地、山脉、障碍、浅水和深水。水域占比目标为 29%–35%，保留多个大陆、岛链、河流和湖泊的视觉结构，但这些结构不需要在运行时重新计算。

### 2.3 固定放置清单

地图随配置提交唯一的初始放置清单：

- 一个玩家出生点及初始建筑坐标。
- 24 个城邦实例，每个实例引用一个城邦资料 ID，并具有固定坐标和陆地/海军领域。
- 96 个野外目标实例，每个实例引用一个野外模板 ID，并具有固定坐标、领域和威胁等级。
- 四种主资源的固定资源点；不引入第五种主资源。
- 必要的港口、远征入口和关键地标。

所有坐标必须唯一、在地图范围内并与地形领域相符。敌对野外目标不得出现在玩家出生点 20 格内；出生区必须有可扩张土地和不超过 24 格的港口通路。城邦、野外目标和资源点在新游戏之间不移动。

## 3. 随机性的保留范围

取消地图种子不等于取消整个游戏的确定性随机。新游戏仍生成或接受 `campaignSeed`，仅用于以下系统：

- 城邦和阵营的目标选择与每日行动。
- 英雄酒馆轮换、关系事件和任务分支。
- 野外目标的守军组合、刷新周期和奖励。
- 贸易风险、叙事事件、任务后果和简化战斗中的有限波动。

相同固定地图、相同 `campaignSeed` 和相同指令序列必须得到相同结果。地图本身不读取 `campaignSeed`。

## 4. 运行时世界所有权

- `WorldMapSystem` 仍是地图查询的唯一所有者，但初始化方式改为加载 `grand_map_v1`，不调用运行时地形生成器。
- 对外保留 `getDimensions()`、`getTile()`、`getBiome()`、`getMapView()`、`getSpawnManifest()`、`findPath()` 和导航修订号等稳定接口。
- 建筑、道路、领土、军团、战斗和渲染系统只读取 `WorldMapSystem` 投影，不复制或改写基础地图。
- 动态变化通过有 ID 的地形差量或领域系统状态保存；恢复时先加载固定基础地图，再原子应用差量。
- 384×384 地图继续使用分块渲染与分层寻路，避免一次创建十几万个 Pixi 显示对象。

## 5. 简化战略战斗

### 5.1 目标

战斗要能解释主要胜负原因、支持英雄与地形差异并正确写回军团状态，但不制作六阶段逐段模拟、阶段动画回放或逐阶段随机轨迹。

### 5.2 结算输入

一次战斗读取双方不可变快照：

- 单位堆栈与基础战力。
- 兵种克制和军团规模。
- 士气、补给和当前损耗。
- 指挥英雄与已生效组合。
- 选定战术。
- 地形、防御工事和必要的天气修正。
- `campaignSeed`、稳定 battle ID 和双方状态修订号。

### 5.3 一次性结算

结算采用一个清晰流程：

1. 计算双方基础战力。
2. 依次应用兵种、英雄、战术、地形、工事、士气和补给修正，并记录来源。
3. 使用 battle ID 派生的确定性有限波动，避免每场完全机械相同。
4. 同时计算双方伤亡、士气变化、补给消耗、胜负以及是否撤退。
5. 校验军团修订号后一次性写回双方；重复或过期提交不得产生第二次伤亡。

预览只显示相对战力、已知修正、预计伤亡区间和撤退风险，不消耗结算随机值，也不改变状态。

### 5.4 简洁战报

战报只需包含：

- 参战双方、胜负和战斗地点。
- 最终修正后战力及主要修正来源。
- 双方伤亡、剩余士气和补给。
- 英雄、兵种克制、地形和战术对结果的主要影响。
- 决定性原因摘要，例如“骑兵在开阔地克制远程部队”。

不要求六个阶段、逐阶段展开表、阶段回放按钮或阶段专属 VFX/SFX。仍保留战斗开始、交锋、胜利、失败和撤退等基础音效类别。

## 6. 内容系统影响

- 城邦、野外目标、殖民和贸易直接引用固定地图实例 ID 与坐标。
- 新殖民目标必须是放置清单中的真实城邦；只有迁移的旧殖民地可以标记为 `legacyOffmap`。
- 野外系统不扫描地图寻找新初始坐标；清除后是否刷新由模板规则决定，刷新默认保留原实例坐标。
- 任务和长期后果引用稳定的城邦、野外目标、区域和地标 ID，因而比运行时随机坐标更容易审计。
- 英雄、文明、时代、外交、贸易、美术、音乐和音效的既定数量与深度目标不因本设计缩减。

在复杂度上，城邦每个结算日最多执行一个主要战略行动；外交使用少量有明确期限和违约后果的条约类型；贸易使用固定地图路径和统一风险结算；殖民使用真实城邦目标、少量治理政策和持续顺从/反抗值；英雄保留等级、任命、技能、关系和组合，但不建立独立的战术小游戏；任务长期后果统一进入可保存、可去重的延迟队列。

## 7. 图像、音乐和音效是硬性产物

- 固定地图必须使用已优化的真实地形贴图和可辨识的城邦、野外目标、资源、军团标记，不以纯文字或开发色块作为最终呈现。
- 英雄头像、单位卡图、城邦徽记、文明标识和关键事件插图必须具有运行时资源路径、加载失败回退和清单校验。
- 允许同类内容共享统一画风、构图模板和图集，但最终资源必须是实际图像文件，并经过尺寸、压缩、透明边缘和界面裁切检查。
- 七时代背景音乐以及建造、训练、研究、时代、外交、贸易、殖民、界面和简化战斗等主要音效类别必须实际绑定到运行时。
- 美术和音频验收不能仅验证“文件存在”；还要验证可加载、被界面或事件引用、音量分组正确，并抽样进行视觉与听觉检查。

## 8. 数据与工具边界

离线构建工具可以保留确定性地形算法，但必须位于开发脚本边界，不被 `main.js` 或运行时系统导入。正式构建需要能够验证固定产物，而不是每次启动重新生成：

- 固定地图配置及其内容校验和受版本控制。
- 离线工具使用固定制作种子时必须产生相同字节，方便审计和重建。
- 人工修正若不能由工具重现，必须作为显式补丁清单受版本控制。
- 发布验证只校验最终固定地图及放置清单，不要求玩家设备承担世界生成成本。

## 9. 验收标准

### 固定地图

- 地图严格为 384×384，所有行宽、地形码、地图校验和正确。
- 八种地形均真实出现；水域和主要陆地区域满足设计预算。
- 24 个城邦、96 个野外目标和资源点数量、ID、坐标、领域均通过校验。
- 玩家出生安全、港口可达、关键目标可寻路，不存在重叠或越界放置。
- 两次新游戏加载相同地图和相同初始坐标；更换 `campaignSeed` 不改变地图。
- 分块渲染和寻路在 384×384 地图上满足既定性能预算。

### 简化战斗

- 相同输入与 campaignSeed 得到完全相同的预览和结算结果。
- 预览无副作用；正式结算只写回一次且同时更新双方。
- 伤亡不超过现有兵力，士气和补给保持合法范围。
- 战报列出主要修正来源和最终结果，不包含伪造的六阶段数据。
- 英雄、战术、兵种克制和地形至少各有一个自动化行为测试。

### 兼容与发布

- v5–v8 存档继续迁移到 v9；旧地图存档保持 `legacy_static`，新游戏使用 `fixed_static/grand_map_v1`。
- 浏览器主流程覆盖新游戏、地图移动、固定城邦/野外目标、一次战斗、保存恢复和至少一个长期任务后果。
- 美术、音乐、音效、内容配额、500 日稳定性和发布检查仍按总计划完成。
- 发布主流程必须实际显示地图贴图、城邦/野外标记、英雄头像和单位卡图，并触发时代音乐与至少一组战斗/外交/殖民音效；文字占位不算通过。
