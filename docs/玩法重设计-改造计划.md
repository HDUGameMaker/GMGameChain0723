# 玩法重设计 — 代码改造计划

> 依据：`docs/玩法重设计文档.md`（玩法层面设计）。
> 本文是代码实现层面的分阶段改造计划。架构（EventBus / Store / config-driven Systems / PixiJS）不动，只重做玩法层。
> 原则：**做减法、聚焦一根主线**；每阶段结束游戏必须可运行；**不删文件**，被砍系统改为"注释接线 + 保留代码"。

---

## 0. 已确认的决策与约束

1. **不删除任何文件/配置**。被砍系统（远征/殖民地/抽象入侵/天气季节/道路/科技树/人文教义/驯兽）的接线注释掉，代码与配置保留。
2. **先建核心循环**，再休眠旧系统。现有乘数系统（科技/人文）后续可重指向"成长引擎"——做"成长"这件事时自然体现，不急于定死。
3. **占有术 = 混合射程**：默认邻接 BFS 扩张（只能从已有领地往外铺），炼金某阶段/药水解锁"远程预铸"（可对任意可见空白格、含不可建地形施法）。
4. 待定项（文档第十一节）一律采用其建议默认值，并做成 `config` 可调（见末尾《待定项默认值表》）。
5. 分支：从 `master` 切 `玩法重设计` 分支（接力项目惯例，避免污染主干）。

## 2. 阶段总览

```
A 核心数据模型(资源/建筑/产出/人口解耦)
B 占领系统(占有术+建筑上限+胜利)
C 敌人x2扩张(空间轴)+战斗清敌(数值轴)+失败
D 炼金重定位(乘法引擎+占术产源+科技并入)
E 旧系统休眠+成长钩子+HUD+存档
F 节奏数值调校
```

依赖：A 是地基；B/C 可并行但 C 的"覆盖领地"依赖 B 的 TerritorySystem；D 依赖 A（乘法挂点）+ B（占术产源）；E 收尾整合；F 最后调数。

---

## Phase A — 核心数据模型重做（资源 / 建筑 / 产出 / 人口解耦）

**目标**：经济自动产出 木/石/食 → 产金设施 → 黄金；人口不再参与生产。

- `config/resources.json`：砍到 4 种 `wood/stone/food/gold`；旧文件备份为 `resources_old.json`。`inspiration`（灵感）随科技并入炼金移除（默认炼金消耗黄金）。
- `config/buildings.json`：砍加工链建筑（`forge/steel_furnace/brick_kiln/machine_shop/lumber_mill/stope/gear_factory` 及 enhanced/advanced 变体）。重定义为三类：
  - **采集器**（木/石/食）：`allowedGrounds` 地形门控产出（木→F、石→R/M、食→G/D）；无 `maxWorkers`，自动产出。
  - **产金设施**：消耗基建资源 → 产出 `gold`。
  - **仓库 / 炼金台 / 训练建筑**：保留并重定义。住宅按"待定项：人口归属"处理（默认养兵）。
- `BuildingSystem._processProduction`：改为自动产出（`perWorker` 概念移除或恒等于 `maxWorkers`）；`output × _getProductionMultiplier`（已存在）接入地形倍率 + 炼金倍率。工人分配路径（`assignWorker/releaseWorker`）注释，保留方法签名防崩。
- `PopulationSystem`：与生产解耦，保留为"养兵食物消耗"sink；`getFoodConsumptionAmount` 改读军队规模而非工人。
- 地形耦合：BuildingSystem 读取 cell `groundType` 决定产出配比/倍率（漏斗形态）。
- 同步清理 `config/adjacency-bonuses.json` 中引用已删建筑 id 的规则（注释失效项）。

**检查点**：进游戏，HUD 显示 4 资源；采集器按地形自动产木/石/食；产金设施产金；全程无人参与。无敌人、无占术。
**风险**：53 个建筑大量改配置；改完跑 `node scripts/verify_bonus_interfaces.js`。

---

## Phase B — 占领系统 / 占有术（TerritorySystem）

**目标**：占术标记格子，建筑也标记，铺满全图 = 胜利；建筑数量上限。

- 新建 `src/systems/TerritorySystem.js`：cell 所有权状态机 `empty / building / possession / enemy`。
  - API：`isOwned(x,y)` / `castPossession(x,y)` / `removePossession(x,y)` / `getOwnedCount()` / `getWinProgress()` / `getOwnedNeighbors(x,y)`。
- **占术施法（混合）**：默认只能从已有领地（building/possession）邻接格 BFS 往外铺；炼金解锁"远程预铸"后可对任意可见空白格（含水域等不可建地形）施法。邻接校验在 TerritorySystem 内。
- **占术成本**：消耗黄金，且随金产出通胀（约束 1：保持"贵到铺不满"）。公式 config 化，如 `baseCost × (1 + inflationRate × totalGoldProduced)`。
- **建筑也算占有**：BuildingSystem 放置/拆除时通知 TerritorySystem 标记/取消。
- **建筑数量上限**：新字段 `buildingCap`（初始小，消耗黄金+资源升级，config 化）；超上限只能用占术占地。`BuildingSystem.place` 校验上限。
- **胜利条件**：所有可占领格（buildable 或可施术地形）被 building+possession 覆盖 → `emit('gameOver', {win:true})`。
- 渲染：`MapRenderer` 加 `_drawTerritory()` 画占术标记（半透明覆盖/纹章）；占术施法模式（复用 placing 状态机）。
- UI：占术施放入口（底部按钮或炼金面板）、建筑上限 HUD、领地进度。
- 存档：`territory` state 入 SaveManager。

**检查点**：能施占术铺地，建筑也占地，铺满全图触发胜利。暂无敌人（可随便铺）。
**风险**：200×200 全图遍历性能 → 用集合存 owned cells + 脏标记，不全量扫描。

## Phase C — 敌人 x2 扩张（空间轴） + 战斗清敌（数值轴） + 失败

**目标**：敌人格刷新 + 倒计时 + x2 扩张；兵清敌；被淹没 = 失败。两轴压力。

- 新建 `src/systems/EnemyExpansionSystem.js`（或大改 CombatSystem 的 enemies 部分）：
  - **刷新**：随日期推进在空白格（非 building/possession）刷敌人；数量/格子数随日增（空间轴）。首刷只在空白格（约束）。
  - **倒计时**：每个敌人格有可见倒计时；到时未清 → 向四周扩张。
  - **x2 扩张**：一个格扩一格，两个格扩两格，每回合翻倍（空间轴 = 格子数翻倍，非人口）。扩张**优先吃玩家相邻格**（约束 6，可预测）。
  - **覆盖**：扩张抹掉 possession、摧毁建筑（大建筑 2×2/3×3 **整栋毁**，不分块掉血，约束 7 = 设计意图）、格变敌方。
  - **数值轴**：单格敌兵强度 = config 按日期曲线（`strength = f(day)`，默认多项式）。难度主旋钮。
- **战斗清敌**：复用 CombatSystem 自动结算 → "军队总战力 vs 格上敌兵强度"，胜则清掉该格敌人。**兵种 combo/配装深度保留**（约束 2 硬约束）。阵型/克制暂沿用现有，Phase F 再调。
- **失败条件**：敌方格数 ≥ 阈值，或扩张触及玩家核心区 → `emit('gameOver', {win:false})`。
- 渲染：`MapRenderer._drawEnemies()` 扩展倒计时显示（数字/进度环）；扩张预警高亮（即将被吃的相邻格）。
- UI：敌人两轴压力指示（空间轴格子数 + 数值轴当日强度）、派兵清敌入口。
- 存档：`enemyExpansion` state。

**检查点**：敌人刷新扩张，兵能清，被淹没触发失败；占术/建筑能挡刷新。
**风险**：x2 指数膨胀性能/数值失控 → 扩张设上限或随清敌减速；强度曲线 config 可调防软锁（约束 3）。

## Phase D — 炼金重定位（乘法引擎 + 占术产源 + 科技并入）

**目标**：炼金 = 给基建产出上乘法（数值轴）+ 产出占有术（空间轴）；科技并入。

- `AlchemySystem.getEffects()`：扩展返回 `gold/baseResource` 产出倍率（养数值轴）。`BuildingSystem._getProductionMultiplier` 已可消费。
- **占术产源**：占术作为炼金的一种产出/解锁。炼金台产出"占术充能"，`TerritorySystem.castPossession` 消耗它（或直接消耗黄金，二选一，默认黄金）。**远程预铸** = 炼金某 Magnum Opus 阶段或特定药水解锁。
- **Magnum Opus 五阶段** → 映射"炼金乘法优化"成长深度 + 远程解锁里程碑。保留阶段渐进（文档待定：五阶段是否保留；默认保留作乘法深度载体）。
- **科技并入**：TechSystem 的解锁作用迁入炼金（兵种/建筑解锁前置 = 炼金阶段）。注释 TechSystem 接线，保留文件；`enemies.json` 的 `prerequisiteTechs` 改指炼金阶段或注释。
- 占术成本通胀（约束 1）与炼金产出曲线联动。

**检查点**：炼金能放大产出、能解锁/产出占术与远程；科技树入口隐藏、解锁走炼金。
**风险**：AlchemySystem 原 880 行实验引擎是否保留？默认保留作"挖掘深度"载体，仅调整产出指向。

---

## Phase E — 旧系统休眠 + 成长钩子 + HUD + 存档

**目标**：注释被砍系统接线，游戏只跑新循环；乘数系统重指向成长；HUD/存档配套。

- `src/main.js`：注释 `Expedition/Colony/Invasion(抽象)/Weather/Road/Torch(若不用于迷雾)/Culture(doctrine)/Taming/Quest(旧)` 的实例化与 `setSystems` 接线。**保留文件**。Torch 若用于敌人可见性则保留，否则一并注释。
- **成长钩子**（用户意图）：`CultureSystem` 的 `productionMul/resourceProductionMul/meleeDamageMul/unitHpMul` 等重指向"成长效率"——喂养炼金乘法 / 军队 scaling。不删，改数据源/触发，服务于"成长超过敌人"的体感。TechSystem 同理（已并入炼金）。
- **HUD**：重做顶部资源栏（4 资源 + 黄金三去向：招兵/升上限/炼金）、敌人两轴压力、领地进度 %、建筑上限。
- **存档**：`SaveManager` 版本号 bump；新 state shape（`time/resources/buildings/territory/enemyExpansion/alchemy/combat/buildingCap`）；改造规模决定旧存档不兼容 → 要求新游戏（保留 migration 框架，默认 `forceNew`）。
- `PopupManager`：注释被砍面板注册（`expedition-*/colony/event-colony/tamed-pool/tech-tree/culture-tree` 等），新增占术/压力相关面板。

**检查点**：完整新循环可玩，旧系统不干扰，存读档正常。

## Phase F — 节奏与数值调校

**目标**：把"待定宏观项"落成 config，调出三阶段曲线（点火/点燃/拉锯），过约束检查。

- config 化（全部可调）：地图大小、首敌第几天、占术/炼金/招兵解锁时机、产出密度、单格强度曲线形态（默认多项式）、占术通胀率、建筑上限曲线、扩张间隔/上限。
- 起手金 + 产出密度双管齐下消除第一幕 dead-time（约束 4）。
- 三条资源漏斗大致平衡、强 situational（约束 5）。
- 扩散可预测 + 倒计时可见 + 优先吃相邻（约束 6）已实现，此处验证。
- 兵种 combo 宽度足够（约束 2）、大建筑整栋毁（约束 7）验证。
- 跑 `verify_bonus_interfaces.js` + 手动 checklist（`test/manual/`）。

## 跨阶段注意

- 每阶段结束跑 `node scripts/verify_bonus_interfaces.js`（改了建筑/资源/加成/单位必跑）。

- 性能：200×200 网格的 territory/enemy 用集合 + 脏标记，不全量扫描。
